- `663-backfill.js`: «Дописати історію» (таблиця днів, без субот/неділь, динаміка на день, генерація щоденників) — **пункт 5 рішень уже зроблено**; не дублювати.
- `270-today.js`: «Пацієнти на сьогодні» — прапорці за знімком (немає щоденника, перегляд АБ, без результатів, етапний епікриз). Основа для «огляду відділення».
- Папка даних / резервні копії / PIN-шифрування (`550`, `605`) працюють із `store` — формат запису змінювати обережно.

## Пропозиція: мінімальна зміна формату

Не вкладати знімки в «пацієнта», а **зв’язати наявні записи**:

```
store[id] = {name, card, dob, updated, snap,
             person: 'u…',        // спільний ключ людини (нове, необов’язкове)
             case:   {n: 2}}      // порядковий номер госпіталізації (нове, необов’язкове)
```

- Записи без `person` — як зараз (нічого не переносимо, старі копії читаються).
- «Пацієнт» = група записів з однаковим `person`; «справа» = один запис.
- Нова госпіталізація = кнопка «Нова госпіталізація цього пацієнта»: копія картки (ПІБ, стать, дата народження, постійні ліки, алергії — задача 21), **порожній огляд**, новий `case.n`. Копіювання діагнозу й тексту огляду з попередньої — не робимо.
- Пошук дубля: той самий ПІБ + дата народження → програма **пропонує** зв’язати, лікар підтверджує (нічого мовчки не зливається).

Чому так: зберігання, резервні копії, PIN, імпорт/експорт, `todayFlags` працюють без переробки; ризик для даних мінімальний (правило 9 — все одно PR без злиття до «зливай»).

Альтернатива (відкинута поки): `patients[id].cases[]` з вкладеними знімками — чистіша модель, але міняє весь шлях збереження, резервні копії й імпорт.

## Хронологія справи (перша версія — лише читання)

Вкладка/картка «Справа»: рядки — календарні дні від надходження до виписки (або сьогодні).
Вихідні — позначка «вихідний», щоденник не вимагається; кнопка «+ запис на вихідний» (рішення 2).

| Колонка | Джерело |
| --- | --- |
| Щоденник | `DIARIES` за `dt` — є / немає / вихідний |
| Показники (t°, АТ, ЧСС, ЧД, SpO₂) | поля щоденника `d_obj.*`; жоден не обов’язковий, порожні дозволені (рішення 3) |
| Призначення | `RX` (початок/кінець/зміни за датою) |
| Обстеження | `RES` за датою |
| Події | надходження, виписка, перегляд АБ 48–72 год, етапний епікриз |

Сьогоднішній день підсвічується. Клік по клітинці відкриває відповідний документ (щоденник за день, журнал обстежень, лист призначень). Внизу — «Дописати пропущені щоденники» (`bfGenerate`), «Епікриз зі справи», «Друк усієї справи» (`packDialog`).

Динаміка в щоденнику — на кожен день, за замовчуванням «з позитивною динамікою»; 3 основні + власні (★) + «ще ›» (рішення 4) — окрема підзадача, після хронології.
