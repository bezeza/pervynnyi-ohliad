# Чекліст зручності інтерфейсу для лікаря

Використовуй його під час аудиту або зміни інтерфейсу первинного огляду, щоденника й інших медичних документів. Це перевірка доступності та взаємодій, а не оцінка медичної коректності.

## Читабельність і стани

- Перевір контраст звичайного тексту на рівні щонайменше 4.5:1, великого тексту — 3:1.
- Не передавай відхилення, помилки чи вибір лише кольором: додай підпис, значок або інший помітний стан.
- Залишай видимий індикатор фокуса на кожному елементі керування. Переконайся, що його не закривають плаваюче вікно, діалог або закріплена панель.
- Використовуй зрозумілі текстові назви дій. Для кнопок лише зі значком задай доступну назву.
- Підтримуй збільшення тексту й перенесення підписів без обрізання важливих чисел, одиниць або назв полів.

## Поля й повідомлення

- Кожне поле має видимий підпис; підказка всередині поля не замінює його.
- Для дат, чисел і пошуку використовуй відповідний тип або `inputmode`. Одиниці виміру показуй поруч із числом.
- Показуй помилку біля поля, якого вона стосується, і програмно пов’язуй її з цим полем (`aria-describedby` або відповідний семантичний стан).
- Не покладайся лише на червону рамку: текст помилки має пояснювати, що виправити.
- Для асинхронної дії покажи очікування, заблокуй повторне натискання та підтвердь успіх або помилку.
- Перевір, що перехід між документами, скасування та закриття редактора не гублять введений текст без зрозумілого попередження.

## Клавіатура, діалоги й плаваючий редактор

- Усі основні дії мають працювати без миші; порядок Tab має відповідати візуальному порядку.
- Перевір Enter, Tab і Escape там, де ці клавіші мають передбачувану дію.
- Після відкриття діалогу фокус переходить усередину й лишається в ньому, доки діалог відкритий; після закриття повертається до елемента, який його відкрив.
- Під час редагування в окремому вікні перевір вставлення в позицію курсора, скасування та відновлення фокуса у вихідному документі.
- На вузькому екрані перевір, що системна клавіатура не закриває активне поле чи кнопку збереження.

## Телефон і різні розміри екрана

- Не ховай важливі дії за наведенням курсора; основні сценарії мають працювати натисканням.
- Для вебу перевір критерій WCAG 2.2 AA щодо цілей натискання 24×24 CSS px та його винятки. Для частих дій на телефоні роби область натискання більшою, якщо це можливо.
- Не змішуй CSS-пікселі з `pt` для iOS або `dp` для Android.
- Перевір ширини 375, 768, 1024 і 1440 px: без горизонтального прокручування, накладених кнопок та обрізаних назв полів.
- Поважай `prefers-reduced-motion`; анімація не повинна затримувати підтвердження дії.

## Перевірка перед завершенням

- Пройди основну дію клавіатурою від початку до кінця й перевір видимість фокуса.
- Перевір порожнє поле, помилкове значення, довгий текст, збільшений масштаб і вузький екран.
- Переконайся, що індикатори помилок, вибору й заповнення зрозумілі без розрізнення кольорів.
- Перевір, що підказки для екрана не потрапляють у друкований документ.
- Не додавай і не змінюй медичні формулювання, норми, діагнози чи схеми лікування за цим чеклістом; їх має перевірити лікар.
