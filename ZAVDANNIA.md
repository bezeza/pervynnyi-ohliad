# Завдання для іншого ШІ — «Первинний огляд»

Основа — свіжий `main` репозиторію `bezeza/pervynnyi-ohliad` (з 0.9.3.34). Сайт (GitHub Pages) оновлюється з `main` автоматично.
Кожна задача = окрема гілка від `main` = окремий PR. **PR зливає сам виконавець — лише при зеленому CI.** У неділю Claude перевіряє все за «Журналом злиттів» унизу.

## Порядок роботи над кожною задачею

1. `git pull` → нова гілка від свіжого `main`.
2. Зробити задачу за правилами нижче.
3. Локально: `node build.mjs`, потім `node tests/features.cjs`, `node tests/full.cjs`, `node tests/workflow.cjs` — усе зелене.
4. `git show origin/main:pervynnyi-ohliad.html > pervynnyi-ohliad-prev.html`, коміт, push, PR.
5. Дочекатися CI на GitHub. Зелений → злити (merge commit, не squash). Червоний → виправити й чекати знову.
5а. **Перед злиттям — `git fetch`.** Якщо `main` змінився з моменту створення гілки (інший виконавець або Claude щось злив): онови гілку від `main`, розв’яжи конфлікти (`120-version-changelog.js`, `manifest.json`, `tests/features.cjs`; зібрані HTML — перезібрати), версія = версія в `main` + 1, дочекайся нового зеленого CI. Лише тоді зливай.
5б. Перед початком задачі — переглянь коментарі у своїх відкритих PR: там можуть бути повідомлення від Claude.
6. Дописати рядок у «Журнал злиттів» (у тому ж або наступному PR), оновити локальний `main`, перейти до наступної задачі.
7. Якщо після злиття щось зламалось — одразу Revert цього PR.

## Правила коду (обов’язково)

1. Код лише в `src/`. Зібраний `pervynnyi-ohliad.html` вручну не правити — його генерує `node build.mjs`.
2. Кожна функція — окремий новий файл `src/js/621-….js`, `622-….js` …, дописаний у кінець `src/manifest.json`.
3. Наявні функції не переписувати, а обгортати: `{ const x0 = fn; fn = function(){ const r = x0.apply(this, arguments); /* своє */ return r; }; }`. Функції, оголошені через `const`, обгорнути не можна.
4. Стилі — у кінець `src/styles.css` з коментарем версії.
5. Кожен PR піднімає версію в `src/js/120-version-changelog.js` (`VERSION`, `VDATE`) і додає рядок на початок `CHANGELOG` українською.
6. Перевірки нової функції — у `tests/features.cjs` перед рядком «Без помилок JavaScript».
7. Жодних даних пацієнтів (ПІБ, дати народження, адреси, номери) у коді, тестах і прикладах.
8. Інтерфейс і тексти — українською; медична термінологія як у наявному коді.
9. Якщо задача вимагає змінити понад 2–3 наявні файли або зачіпає збереження пацієнтів — зупинитися, описати в PR і **не зливати**.

Тепер це поля `d_obj.*` + `bFS(bFill(...), 'd_obj.ключ')` (клік відкриває вибір). Перевірити так само ВСІ бланки (`366-blank-003.js`, `612-f066.js`, `614-anest.js`, 027/о в `615-epi-hosp.js`):
    1. рядки з `bFill('')` — порожні місця без поля у формі;
    2. зашиті фрази-норми, що друкуються завжди, незалежно від даних (як було «Сечовипускання вільне, не болюче, діурез достатній»);
    3. рядки, клік по яких нічого не відкриває.
    У PR — таблиця: бланк · рядок · що зараз · що пропонується. Порожнє місце, яке лікар і так вписує ручкою, можна лишити — позначити в таблиці. Зашита «норма» без даних має стати полем або порожнім рядком. Нові медичні варіанти — PR без злиття (як 10–12).

Поведінку програми й перевірки не змінювати — лише розподіл. У PR: час до і після. Змінює лише CI-файл і, за потреби, `package.json` — можна злити після зеленого прогону.

- [ ] **15. Упорядкування `src/` без зміни поведінки** *(PR без злиття)*. Поступово замінювати ланцюжки обгорток (`{ const x0 = fn; fn = … }`) прямими змінами в одному місці — лише там, де це безпечно. Обов’язкова умова: після збірки `pervynnyi-ohliad.html` має бути побайтово ідентичним до `main` або відмінності пояснені в PR. Задача торкається багатьох файлів — за правилом 9 не зливати.
