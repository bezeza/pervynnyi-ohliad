# H24 на комп’ютері і перенесення в «Первинний огляд»

МІС Health24 (`mis.h24.ua`) потрібна для статистичної звітності послуг. У неї немає відкритого API, а на комп’ютері дрібний шрифт, довгий ряд вкладок і щільні картки. Ці файли лише змінюють вигляд і **читають уже відкритий екран**.

Усе відбувається у вашому браузері. Скрипти не надсилають дані пацієнта в інтернет, не пишуть у МІС і не натискають «Зберегти», «Підписати», «Надіслати» чи «Отримати доступ».

Файли (після злиття в основну гілку):

- стиль: https://raw.githubusercontent.com/bezeza/pervynnyi-ohliad/main/tools/h24/h24-comfort.user.css
- той самий вигляд скриптом, якщо Stylus немає: https://raw.githubusercontent.com/bezeza/pervynnyi-ohliad/main/tools/h24/h24-comfort.user.js
- кнопка перенесення: https://raw.githubusercontent.com/bezeza/pervynnyi-ohliad/main/tools/h24/h24-to-pervynnyi.user.js

## Що гарантовано

- **Лише читання.** Скрипт дивиться на те, що вже намалювала сторінка, і копіює це в буфер обміну. Поля МІС не змінюються. Кнопки «Зберегти», «Підписати», «Надіслати» й «Отримати доступ до медичних даних» він не натискає.
- **Без мережі.** Немає запитів до серверів, у тому числі до GitHub під час роботи. Дані не залишають браузер: буфер обміну → «Первинний огляд» на цьому ж комп’ютері.
- **Підтвердження.** У програмі нічого не записується, доки ви не побачите список полів і не натиснете «Заповнити».
- Стиль теж нічого не ховає: довгі фільтри й ряд із 30 вкладок лишаються, їх можна прокрутити.

Окремий старіший скрипт `extras/mis-h24-plus.user.js` («→ ПО») копіює лише короткий рядок ПІБ. Його можна лишити. Нова кнопка називається «→ в Первинний огляд» і несе ще епізоди, діагнози, алергії й ліки.

## Stylus у Chrome або Edge

1. Відкрийте інтернет-крамницю: [Stylus для Chrome](https://chromewebstore.google.com/detail/stylus/clngdbkpkpeebahjckkjfobafhncgmne) або [Stylus для Edge](https://microsoftedge.microsoft.com/addons/detail/stylus/kdbmlkajjpfhldjnfpedbajjhgeebjln). Натисніть «Додати» / «Отримати».
2. Відкрийте сире посилання на стиль (перше в списку вище).
3. Якщо Stylus запропонує встановити стиль — погодьтеся.
4. Якщо ні: значок Stylus → «Керування» → «Написати новий стиль» → вставте весь текст файлу → «Зберегти». У файлі вже є правило `@-moz-document domain("mis.h24.ua")`, окремо адресу прописувати не треба.
5. Оновіть вкладку МІС. На широкому екрані (від 1100 px) шрифт стане 15 px, рядки — вищі, цілі для миші — більші, картка пацієнта — читабельніша. Вкладки «Епізоди», «Історії», «Діагноз», «Документи», «Звіти» виділені. Таблиці — смугами, шапка тримається при прокручуванні.

## Tampermonkey або Violentmonkey

Потрібно, якщо ставите скрипт вигляду без Stylus і обов’язково — для кнопки перенесення.

1. Крамниця: [Tampermonkey для Chrome](https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo), [Tampermonkey для Edge](https://microsoftedge.microsoft.com/addons/detail/tampermonkey/iikmkjmpaadaobahmlepeloendndfphd) або [Violentmonkey для Chrome](https://chromewebstore.google.com/detail/violentmonkey/jinjaccalgkegednnccohejagnlnfdag).
2. Відкрийте сире посилання на `.user.js`. Менеджер скриптів покаже сторінку встановлення — «Встановити».
3. Поставте обидва, якщо Stylus немає: спершу `h24-comfort.user.js`, потім `h24-to-pervynnyi.user.js`. Зі Stylus досить лише другого.
4. Перевірте, що скрипти увімкнені для `https://mis.h24.ua/*`.

## Як перенести пацієнта

1. У МІС відкрийте **медкарту конкретного пацієнта** (адреса містить `/patients/…/medical-card/`). Зачекайте, доки картка домалюється: дані з’являються через кілька секунд.
2. Натисніть плаваючу кнопку **«→ в Первинний огляд»** (праворуч знизу). Якщо екран ще порожній, кнопка сама почекає до 5 секунд.
3. З’явиться коротка картка лічильників: чи є ПІБ, дата, стать, і скільки епізодів, діагнозів, алергій і ліків. Повного тексту там немає — він уже в буфері. Напис «Скопійовано в буфер» означає, що можна йти в програму.
4. Відкрийте «Первинний огляд» і натисніть **«Імпорт з H24»** (поруч із «⇩ З МІС»; на екрані «Пацієнти» — біля «Новий пацієнт»).
5. Програма покаже, **що саме запише**: ПІБ, дату народження, стать, діагноз із кодом МКХ-10, супутні, алергії й ліки (ліки — рядком у «Додатково»). Якщо пацієнт із таким ПІБ і датою вже є, відкриється його картка і допишуться лише порожні поля.
6. «Заповнити» — записати. «Скасувати» — нічого не змінювати.
7. Якщо браузер не дав прочитати буфер, вставте JSON у поле внизу вікна (Ctrl+V) і натисніть «Перевірити».

На списку `/patients/list` кнопки немає навмисно: інакше можна схопити не того пацієнта.

## Що саме зчитується

Точної розмітки H24 у репозиторії немає, тому розбір тримається за стійкі ознаки. Якщо на екрані чогось не видно — у JSON буде порожньо, програма це поле не вигадає.

- **ПІБ:** `data-test="patientFullName"`, `.patient_title`, пара «ПІБ» у блоці на кшталт `.h24-popover__key-value`, заголовок вкладки.
- **Дата народження:** `data-test="birthDate"` або підпис «Дата народження» (`21.04.1973` чи `21 квітня 1973`).
- **Стать:** `data-test="gender"` або підпис «Стать». Якщо порожньо — з по батькові.
- **Епізоди:** таблиця під заголовком «Епізоди» або на вкладках `patient-summary` / `histories`. Шапка може бути звичайним першим рядком, без `thead`. Шукаються код МКХ-10 (латиниця, напр. `J18.1`), назва, статус, дати.
- **Діагнози:** таблиця під «Діагноз» / вкладка `diagnosis`: тип (основний, супутній), назва, код.
- **Алергії та ліки:** лише якщо вони вже на екрані — підпис «Алергії», «Лікарські засоби», «Препарат» або список під таким заголовком. Окремої вкладки алергій у нотатках структури не знайдено.

У «Первинний огляд» з діагнозів береться основний (або перший). Якщо діагнозів на екрані не було — активний епізод (не «завершений» і не «закритий»). Решта епізодів у документ окремими записами не перетворюється: їхня кількість лише показана у підтвердженні.

## Обмеження

- Це евристика. Якщо H24 змінить підписи або заховає текст у закритий shadow DOM, поле лишиться порожнім — у вікні підтвердження це видно.
- Зчитується тільки те, що зараз намальовано. Інші вкладки медкарти самі не відкриваються.
- Скрипт не обходить «Отримати доступ до медичних даних»: доки МІС не показала дані, копіювати нічого.
- Статистичний звіт послуг як і раніше робиться в самій H24. Сюди переноситься чернетка огляду, не звіт.
- Перед підписом документа звіряйте ПІБ, дату, стать і код МКХ із карткою в МІС.

Синтетична сторінка для перевірки вигляду й розбору (вигаданий «Тестовий Пацієнт», без справжніх даних): `tools/h24/fixtures/synthetic-patient.html`.
